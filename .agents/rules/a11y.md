# Accessibility Rules

## WCAG 2.2 AA Compliance

- Contrast ≥ 4.5:1 for text, ≥ 3:1 for large text and UI components.
- Every interactive element: visible focus ring, 44×44px min touch target.
- `prefers-reduced-motion` respected everywhere.
- axe-core: zero violations on every main page.

## Instrument-Specific Accessibility

### Keyboard Navigation

- Piano: computer-keyboard mapping (documented key map), octave shift via keyboard shortcuts.
- Guitar fretboard: arrow keys navigate strings and frets, Enter/Space to play.
- Chord diagram: Tab through alternatives, Enter to select, Space to play.
- Harmonium: same keyboard mapping as piano with sargam labels announced.
- Circle of fifths: arrow keys rotate, Enter selects key.
- All keyboard mappings documented in a discoverable help panel.

### Screen Readers

- ARIA live regions for "now playing" announcements (e.g., "C major: C, E, G").
- SVG instruments have `role="img"` with descriptive `aria-label` OR `role="application"` with individual interactive elements labeled.
- Chord diagrams announce: chord name, fret positions, finger assignments.
- Theory panel explanations are semantically structured (headings, lists), not visual-only.

### Visual Accessibility

- Role language (root, third, fifth, seventh) uses shape, label, or pattern IN ADDITION to color. Never color alone.
- Note labels on instruments are always available (names, intervals, degrees, or sargam — user's choice).
- Decorative images use `alt=""`. Meaningful images have descriptive alt text.

### Touch

- All instrument touch targets ≥ 44px on mobile.
- Multi-touch supported on piano (play chords with fingers).
- Fretboard vertical orientation on mobile for comfortable thumb reach.
